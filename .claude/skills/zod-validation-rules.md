# Zod Validation Rules\n\nStandards for validating Express request bodies, route parameters, and query strings with reusable Zod schemas.\n\n## When to Use\n\nReference this skill when adding or changing an Express endpoint, request DTO, input-validation middleware, or API error response in `apps/api/`.\n\n---\n\n## Patterns\n\n### Define schemas by request location\n\nKeep schemas in a feature-local validation module (for example, `src/routes/conferences.validation.ts`) and export schemas and inferred types from the same source of truth.\n\n```typescript\nimport { z } from 'zod';\n\nexport const conferenceParamsSchema = z.object({\n  id: z.string().uuid(),\n});\n\nexport const listConferencesQuerySchema = z.object({\n  page: z.coerce.number().int().positive().default(1),\n  limit: z.coerce.number().int().min(1).max(100).default(25),\n  status: z.enum(['draft', 'published', 'archived']).optional(),\n});\n\nexport const createConferenceBodySchema = z.object({\n  title: z.string().trim().min(3).max(100),\n  description: z.string().trim().max(2_000).optional(),\n  startsAt: z.coerce.date(),\n  endsAt: z.coerce.date(),\n}).refine(({ startsAt, endsAt }) => endsAt > startsAt, {\n  message: 'endsAt must be after startsAt',\n  path: ['endsAt'],\n});\n\nexport type ConferenceParams = z.infer<typeof conferenceParamsSchema>;\nexport type ListConferencesQuery = z.infer<typeof listConferencesQuerySchema>;\nexport type CreateConferenceBody = z.infer<typeof createConferenceBodySchema>;\n```\n\n- Use `z.object(...)` schemas for each Body, Params, and Query surface; do not reuse one schema where their shapes differ.\n- Use `z.coerce` for URL/query values that arrive as strings. Avoid coercion for JSON fields unless the API explicitly accepts multiple representations.\n- Apply constraints at the boundary: trim strings, bound lengths, validate UUIDs/enums/formats, and reject unknown fields with `.strict()` for security-sensitive payloads.\n- Compose shared fields with `.pick()`, `.omit()`, `.extend()`, or reusable field schemas rather than duplicating rules.\n\n### Validate once in middleware\n\nParse all request surfaces before entering the route. Replace request values with parsed output so downstream code receives normalized types.\n\n```typescript\nimport type { NextFunction, Request, Response } from 'express';\nimport { z, type ZodTypeAny } from 'zod';\n\ntype RequestSchemas = {\n  body?: ZodTypeAny;\n  params?: ZodTypeAny;\n  query?: ZodTypeAny;\n};\n\nexport function validateRequest(schemas: RequestSchemas) {\n  return (req: Request, res: Response, next: NextFunction) => {\n    const result = z.object(schemas).safeParse({\n      body: req.body,\n      params: req.params,\n      query: req.query,\n    });\n\n    if (!result.success) {\n      return res.status(400).json({\n        error: {\n          message: 'Validation failed',\n          code: 'VALIDATION_ERROR',\n          details: result.error.issues.map((issue) => ({\n            path: issue.path.join('.'),\n            message: issue.message,\n            code: issue.code,\n          })),\n        },\n      });\n    }\n\n    if (result.data.body) req.body = result.data.body;\n    if (result.data.params) req.params = result.data.params;\n    if (result.data.query) req.query = result.data.query;\n    return next();\n  };\n}\n```\n\n```typescript\nrouter.post(\n  '/',\n  validateRequest({ body: createConferenceBodySchema }),\n  async (req, res) => {\n    const input = req.body as CreateConferenceBody;\n    const conference = await store.createConference(input);\n    res.status(201).json({ data: conference });\n  },\n);\n```\n\n### Preserve the error envelope\n\nAll validation failures use exactly this public shape:\n\n```typescript\n{\n  error: {\n    message: 'Validation failed',\n    code: 'VALIDATION_ERROR',\n    details: [\n      { path: 'title', message: 'String must contain at least 3 character(s)', code: 'too_small' }\n    ]\n  }\n}\n```\n\n- `message` is a safe, human-readable summary.\n- `code` is a stable application code, not a Zod implementation detail.\n- `details` is an array of field-level issue objects; never expose stack traces or internal data.\n- Use HTTP `400` for malformed input. Reserve `422` only if the project deliberately distinguishes syntactically valid but semantically invalid requests.\n\n---\n\n## Anti-patterns\n\n```typescript\n// ❌ Duplicate interfaces that can drift from runtime validation.\ninterface CreateConferenceInput { title: string; }\nconst schema = z.object({ title: z.string().min(3) });\n\n// ✅ Infer the type from the schema.\ntype CreateConferenceInput = z.infer<typeof createConferenceBodySchema>;\n\n// ❌ Parse individual values ad hoc inside every route.\nconst page = Number(req.query.page) || 1;\nif (!req.body.title) return res.status(400).json({ message: 'Bad input' });\n\n// ✅ Validate and normalize once with shared middleware.\nrouter.get('/', validateRequest({ query: listConferencesQuerySchema }), handler);\n\n// ❌ Return raw Zod errors or inconsistent payloads.\nres.status(400).json(result.error);\nres.status(400).json({ message: 'Invalid input' });\n\n// ✅ Return the standard API error envelope.\nres.status(400).json({ error: { message, code, details } });\n```\n\n---\n\n## References\n\n- `apps/api/src/routes/`\n- `apps/api/src/types.ts`\n- `apps/api/src/app.ts`\n- `.claude/skills/backend-patterns.md`\n- [Zod documentation](https://zod.dev/)
